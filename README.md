## 🌟 Overview

**Tuli-QA** is a modern Quality Assurance portfolio designed to present professional information in an engaging and interactive way.

The application combines a polished portfolio interface with reusable UI components, responsive layouts, data-driven sections, and an AI-powered assistant.

The goal is simple: **present professional QA experience clearly while demonstrating modern frontend development practices.**

## 🚀 Getting Started

### 1. Clone the repository

```bash
git clone https://github.com/mehadeehassan/Tuli-QA.git
```

### 2. Navigate to the project

```bash
cd Tuli-QA
```

### 3. Install dependencies

```bash
npm install
```

### 4. Start the development server

```bash
npm run dev
```

The application will be available at:

```text
http://localhost:5173
```

---

## 🏗️ Production Build

Create an optimized production build:

```bash
npm run build
```

Preview the production build locally:

```bash
npm run preview
```

## 🤖 AI Assistant

Tuli-QA includes an AI-powered assistant designed to make the portfolio more interactive.

The assistant can be configured to provide information about:

- Professional experience
- QA expertise
- Technical skills
- Projects
- Education
- Career background

### Environment Variables

Create a `.env` file in the project root:

```env
OPENAI_API_KEY=your_openai_api_key
```

> ⚠️ Never commit API keys, tokens, passwords, or other sensitive credentials to GitHub.

## 🎯 Project Goals

Tuli-QA was built with the following goals in mind:

- Present QA experience in a professional and modern format
- Showcase testing and technical expertise
- Highlight real-world projects and achievements
- Provide an interactive portfolio experience
- Demonstrate modern React and TypeScript development
- Integrate AI into a practical portfolio use case

---

## 🧩 Architecture

The project follows a component-driven architecture with a focus on:

- Reusability
- Maintainability
- Type safety
- Responsive design
- Separation of concerns
- Accessible UI patterns
- Modular feature development
- Environment-based configuration

This structure makes it easier to add new portfolio sections and extend existing functionality without introducing unnecessary complexity.

---

## 🔒 Security

The project follows basic security best practices:

- API credentials are stored through environment variables.
- `.env` files should not be committed to source control.
- Sensitive information should never be hardcoded into client-side components.
- Production secrets should be configured through the deployment platform.

---

## 🌐 Deployment

Tuli-QA can be deployed to modern frontend hosting platforms such as:

- Vercel
- Netlify
- Cloudflare Pages

When deploying the AI functionality, make sure the required environment variables are configured in the hosting platform.
